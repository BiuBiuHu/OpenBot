## 1. 当前结论

- 是否可以进入 PRD/UI/架构：可以。目标、闭环、验收证据已齐。
- 是否需要竞品/通用方案调研：需要，已写入 `00-research/competitor-research.md`。
- 是否需要用户确认：用户已书面放弃审核关卡，并允许测完的代码合入默认分支。发布仍禁止。
- 当前最大风险：把「只分发」旧决策和「必须先 HTTP 读公开文档」新事实写拧，或把工作区文稿产品误当成已交付。

## 2. 目标澄清

- 用户真正想完成的业务结果：同一个人、同一条聊天，能用四种能力——聊天、经 ECS 上 OpenHands 改代码、文档、能看能接管的 ECS 桌面。本增量先修好「贴公开文档链接问讲了什么」：必须抓到页、用 Settings 语言回几句，不得当成空电脑任务超时。
- 主要用户/角色：在自己笔记本打开 OpenBot 页的人（生湖及后续同类使用者）。
- 核心操作闭环：打字 → 本机主服务分流 →（文档）HTTP 读公开页 → 短答出现在同一线程。失败则一句人话，可再说一次。
- 工作单元和批量范围：单条消息。不做批量抓取、不做文档库。
- 成本、时延和质量约束：文档抓取本机超时约 8 秒；回复几句；默认 `zh-CN`；不新增模型调用；不部署。
- 返工/重试/回滚粒度：人再发一句。代码回滚=还原本 feature 的 commit。
- 已向用户确认的结论：一条聊天；四种能力；三台机器分开说；Settings 语言；桌面 16:10 只画帧缓冲；决策进本目录；测完可合 `main`；新分支从同步后的默认分支开；不打印密钥；不部署。
- 仍需反问用户的问题：无。用户已要求直接推进。后续能力（具名改文件、工作区文稿、桌面接管新交互）进 backlog，不在本增量发明细节。

## 5. 状态、权限和环境

- 状态机：人发一句 → thinking → 文档路径抓取 → 成功短答 / 读不成一句 /（其它路径）交接。无文档对象状态。
- 角色权限：单人本机。无多租户。
- 预发/线上差异：无共享预发、无生产。只验证笔记本环回页与本地测试。
- 数据来源：公开 HTTP 正文；Settings 语言；不写数据库。
- 数据写入和副作用：评测记录只进 `~/.openbot/evals/`（0600）。不写 ECS，不存私钥正文。

## 6. 边界、异常和成本保护

- 空态：抓到空正文 → 「这个链接我没读成。」
- 错误态：非 HTTP、超时、非 2xx → 同上，不是「没在时限里跑完」。
- 慢请求/超时：抓取默认 8s；真超时仍可一句；禁止用电脑任务超时句冒充读文档。
- 重复提交：每句独立抓一次。无缓存键（本增量无昂贵模型）。
- 并发/顺序：单线程聊天；不并行抓一堆 URL。
- 旧数据/旧客户端兼容：同一 `POST /api/chat`，无新字段。
- AI/生成成本保护：文档路径不调本地/远端模型。
- 缓存/对象存储复用：无。
- 最小返工粒度：人改口再发。
