## 1. 问题摘要

- 问题现象：人发送「看看 https://github.com/bojieli/ai-agent-book/blob/main/book/chapter3.md 这个文档讲了什么?」，回复只有「这台电脑这轮没在时限里跑完。你再说一次就行。」
- 影响环境：本机 OpenBot 页 + 已配置的 ECS 交接（具体主机不入库）。
- 影响用户/角色：本机使用者。
- 严重级别：P0。文档能力看起来完全不可用。
- 当前状态：v0.1 的「看看…讲了什么」评测已绿，但不是用户后打的原句。v0.2 针对原句与真抓取补洞。

## 2. 复现信息

- 环境：已合入 `main` 的本机客户端（`c43e14d` 一带）。
- 版本/commit：复现于归并后的现场页，不是未合并草稿。
- 账号/权限：本机 Settings 已连电脑。不记录密钥。
- 操作步骤：在唯一输入框粘贴上述中文问句并发送。
- 期望结果：抓到公开页，用简体几句说明这一章在讲用户记忆/知识库。
- 实际结果：交接路径超时口吻。
- 复现稳定性：稳定。问句不含「是什么」，`LOOKUP_ASK` 不中；含 URL 但无文档分流，于是 `forceHandoff: true` 进 OH。
- 截图/日志/API 响应：用户口述 shown 全文即超时句。仓库不存主机日志。

## 4. 根因

- 根因层级：主服务分流，不是 ECS 宕机。
- 具体原因：没有「带 URL 的读文档问句」路径。该句不是查找、不是时钟、不是含糊改代码，被当成电脑任务。`LOOKUP_ASK` 匹配「是什么/什么是」，不匹配「讲了什么」。
- 为什么之前没发现：chat-layer 没有这条现场原句；阶段笔记还把公开页排除在文档能力外。

## 5. 修复方案

- 修改范围：`page-read.ts`、thread 文档分支、document 口吻、eval `read-public-doc`、相关测试。
- 不修改范围：OH 超时阈值、桌面、SSH、查找百科路径、工作区文稿产品。
- 风险：误把普通带 URL 的句子当文档。缓解：必须同时有 URL 与文档问法/`.md`。
- 回滚方式：删除 document 分支。
