# 阶段 3 · 文档

独立文档。评审应能只读这一份就否定它。本阶段**尚未实现**。未实现却标绿，本阶段作废。

本阶段开始前，阶段 1 与阶段 2 的评测必须全绿。其中任一阶段有一条红，本阶段不得绿。

## 目标

人在**同一条聊天**里使用「文档」能力：让 Agent 在 ECS 上读、写、改人在乎的文稿（说明、记录、纪要），并在同一条线程里看到结果。

中间层仍然只分发。它不在 Agent 看见之前把「帮我写一份说明」分到本机模板，也不把文档做成第二条聊天。

## 非目标

- 不做云端网盘、团队空间、权限矩阵。
- 不把公开网页抓取冒充「用户的文档」（那是「不是产品」的网页）。
- 不在本阶段验收桌面里打开的办公套件像素操作（阶段 4 可以看见桌面，但文档能力的及格线是工作区里的文稿，不是认窗口）。
- 不实现本阶段。不合并 PR #7。

## 当前事实

1. 仓库里**没有**文档产品：没有文稿列表、没有上传入口、没有「文档」对象模型。
2. `evals/chat-layer/cases/links-render.json` 只保证回复里的 URL 变成 Markdown 链接。人说的是「文档在哪」，夹具是 `https://example.com/docs`。这不是文档能力。
3. 聊天中间层若仍按阶段 0 现状运行，含「写一份」的句子可能被 `isComputerTask` / 交接或本地口吻吃掉；阶段 1 完成后，这类句子应原样到 Agent。见 [01-chat.md](01-chat.md)。
4. ECS 工作区可以有普通文件。那是 OpenHands 的文件系统，不是本产品已经验收的「文档」能力。
5. 三台机器仍然分开。笔记本页没有文档柜。example.com 不是用户文档。

## 设计

1. **先重跑阶段 1 + 2。** 聊天抢答或改代码评测红，本阶段不开工标绿。
2. **文档 = 同一条聊天里、落在 ECS 工作区的文稿。** 人可以请 Agent 起草、改一节、读回要点。中间层不提供本机「生成一篇」的模板引擎。
3. **不要第三条 mode。** 没有「文档」页签和聊天抢焦点。
4. **语言。** 读出和写出的人话服从 Settings 语言。文稿正文的语言听人的要求；人没说则跟 Settings。
5. **不是产品的网页。** Agent 为了写文档去打开百科，那是外部页，评测不得把百科 HTML 当用户文档。

评审若认为「文档」应是笔记本本地库而不是 ECS 工作区，请否定第 2 条，不要在实现里默默改掉。

## 现场页怎么验收

1. 重做阶段 1、阶段 2 的现场步骤。任一步失败，本阶段失败。
2. 请 Agent 写或改 ECS 工作区里的一份 `.md`（或人指定的文稿名）。同一输入框，同一条线程。
3. 回复是人话。不要把整篇文稿和工具日志糊在聊天里当唯一输出；文稿在 ECS 上。
4. 右边电脑卡片不是本阶段及格条件。若它开着，仍须无 noVNC 工具条、16:10、可放大（阶段 4 的约束已经存在于壳上，本阶段不得拆掉）。
5. 无密钥、无 PEM、无非环回地址进页面或评测。
