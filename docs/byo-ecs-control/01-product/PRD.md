# 独立可扩展 Bot · 首版 PRD

## 0. 版本历史
v0.1 / 2026-11-20：基于用户已批准的 ECS 垂直链路实施；安派只作为未来 API 消费端。

## 1. 当前决策
保留独立仓库与测试入口，不把代码、模型 SDK、SSH 或运行时依赖引入安派。首版单用户，按自然语言提交完整委托；ECS 常驻执行；本机负责观察和审批。

## 2. 需求验证结论
沿用 requirement-validation.md 的 REQ-ECS-001～007。文件写入通过受审批的 OH 工具；文件浏览和预览由独立接口提供。下载、真正进程级取消和长期对话记忆尚未实现，不混同已交付。

## 3. 目标澄清
用户在独立入口提交一个可交付任务，离开后再回来查看结果，文件实际存在于自己的机器；任务不因刷新重复执行。费用沿用用户模型配置，测试仅一个小任务。

## 4. 用户、问题与场景
个人拥有 ECS。典型委托：在工作区整理一份 notes.md。核心问题是断网或关机导致失去进度，不知道任务是否完成，以及重试可能重复操作。

## 5. 范围
包含 SSH 接入、自然语言任务、工具审批、文件预览、任务持久化和重连。排除安派仓库修改、公开多租户服务、桌面浏览器、周期调度和云实例购买。

## 6. 核心流程
打开 /bot → 恢复连接 → 提交目标 → 获得 taskId → 必要时批准实际工具动作 → 可关闭客户端 → 重开读取原任务及文件。拒绝动作/暂停后保持明确状态；未知提交结果先对账，不自动重做。

## 7. 验收标准
001 主机与 runtime 归属正确；002 实际命令输出；003 notes.md 内容与预览相同；004 本地主服务退出后远端完成并恢复同一 ID；005 审批在执行前；006 requestId 去重、不确定状态不重发；007 文件边界和预览限制。各项具体用例与证据见测试策略/报告。

## 8. 版本节奏
当前先交付单机独立闭环。下一阶段补产物下载、完善任务终止与事件流；安派接入单独增量，只调用版本化 API。

## 9. 未解决问题
现有测试 OH 以 root 运行，本次不改它的账户或部署。当前是用户信任其主机的测试环境，不声称具有隔离恶意工具的沙箱。
