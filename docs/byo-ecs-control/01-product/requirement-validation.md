# 用户自带 ECS：需求验证

## 0. 版本历史

| 版本 | 日期 | 变更 | 原因 | 影响 |
|---|---|---|---|---|
| v0.1 | 2026-11-20 | 确认首版核心闭环 | 用户选定命令、文件、长期任务 | 桌面和浏览器接管后置 |

## 1. 当前结论

可以形成可审技术方案。初稿按 `manual-gated` 规划推进：本轮原始请求是看项目、参考开源并研究如何实现，后续要求遵循 opc-skills；本轮产物是调研和方案，不把选项回复推定为生产部署批准。

2026-11-20 后续用户明确授权继续实施，现进入 `implementation-loop`；代码保持独立，不修改安派仓库。真实测试沿用用户确认的既有配置。

最大风险是把“ECS 执行了一条命令”误当作“完整 Agent 可持续运行并恢复”。现有实现差距见 [调研](../00-research/competitor-research.md)。

## 2. 目标澄清

- 用户：拥有一台 Linux ECS、SSH 访问权及模型凭证的个人。
- 结果：在 OpenBot UI 用自然语言安排任务，文件真正落在自己的 ECS，关闭本机后已接收的任务继续工作；重开 UI 查到结果或待审批项。
- 核心闭环：添加电脑 → 检查/安装 → 聊天提交 → 远端接收并持久化 → 进度或审批 → 结果与文件 → 重连恢复。
- 工作单元：一条任务。建议首版一台主机、一个用户、一个可写工作区，写任务串行；不做多用户隔离平台。
- 已确认：用户选择“聊天执行命令、读写文件、运行长期任务”。
- 规划假设：沿用本地 UI/主服务，经 SSH 访问 ECS；已交给 ECS 的完整任务可独立运行，本地尚未提交的规划不保证合盖后继续。
- 成本建议：用户 BYOK，预检不调用付费模型；验收使用一次小任务；最大迭代、输出量和任务预算显式配置，刷新不重新调用模型。具体金额上限在真实测试前配置。
- 恢复粒度：重新连接已有任务，不默认重新执行。服务重启后无确定恢复能力的命令标记中断/待核对。

## 4. 歧义、冲突和隐藏假设

| 问题 | 处理 |
|---|---|
| “长期”是否包括周期调度 | 首版定义为已提交任务持续执行；定时任务另立需求 |
| “操作 ECS”是否指云厂商控制台 | 首版是通过 SSH 操作现有实例；不需要阿里云 AccessKey，不自动购买、销毁或调整实例 |
| 文件在笔记本还是 ECS | 任务工作区和产物在 ECS，本机只缓存索引及显示内容 |
| README 的旧 handoff 与当前 Pi 行为不同 | 以当前 Pi + 动态 agent card 为实现基线；不恢复强制切换模式或每次交接确认 |
| 断网与实例重启 | 断网不终止任务；实例/执行进程重启不承诺任意程序恢复，保留证据并标明中断 |
| 不安装桌面是否影响首版 | 不影响；shell/files 可用即可，缺少 VNC 不应阻断连接 |

## 5. 状态、权限和环境

- 任务：queued → running → waiting_approval → running → succeeded / failed / cancelled / interrupted。
- 连接：disconnected / connecting / online；与任务状态分离。客户端失联只表示无法观察。
- 用户明确授权任务目标；对执行时额外出现的高风险操作在远端执行前审批，不以简单字符串分类保证安全。
- 本地配置保留 SSH 私钥路径；私钥不发送给模型、不上传 ECS。远端使用独立普通账户，服务凭证不进入日志或会话。
- 开发为本地 mock；真实联调使用指定测试 ECS 和独立工作区；生产尚未指定、未批准。

## 6. 边界、异常和成本保护

- 空态提示连接机器；无能力不伪造执行结果；缺模型配置应在提交前说明。
- 同一 requestId 重试返回同一 taskId。已被远端接收但响应丢失时先查询，禁止盲目新建。
- 同一线程任务保序；文件写入需冲突检测或串行处理。路径穿越、符号链接逃逸、敏感目录和超大文件需要负向验证。
- 已存在文件修改前预览差异或保留版本；拒绝审批后不得写入。备份不等于所有 shell 操作可回滚。
- 本地旧 worker 和新 Agent 路径不互相静默降级，防止重复执行。
- 结果缓存按 hostId/taskId/artifactId/version 使用，查看和重连只读取证据。

## 8. 未解决问题

真实 ECS 访问方式和环境尚未核实；需要在部署前确认测试目标及资源/费用边界。用户若要求纯公网网页、无需本地服务，则需新增设备配对、远端网关和 HTTPS 方案，本轮不默认扩张到该范围。
