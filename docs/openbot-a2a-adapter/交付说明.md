这份说明跟着 `architecture.md` 的方案走。方案还没当成已经做完。还没有在用户的真实页面上验证。不要合并。

## 适配层放在哪

适配层源码写在 OpenBot 仓库，不改 OpenHands 上游。它是给我们自己部署的那份 OpenHands 准备的，这次不装上去。

因此：现网那份 OpenHands 在部署之前仍然不会发 agent card。没有卡时，代码不得假装已经走了 A2A。只能等以后部署时，把仓库里的适配层放到那份 OpenHands 前面。官方自己发卡之后，这层可以拿掉。

## 这次明确不做

- 不部署。
- 不 SSH。
- 不改用户机器上的文件。
- 不把密钥、PEM 或公网 IP 写进仓库。
- 不合并。

## 代码落地之后要能证明的事

方案写成代码之后，测试要能看出这三件事：

- 基础问答由 Pi 自己短回。
- 改文件或跑命令会发成 A2A 任务，不是 Pi 自己做。
- 没有 agent card 时，不假装已经走了 A2A。
